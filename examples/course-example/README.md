# Example: course profile

Этот каталог — пример проекта, инициализированного как `course` профиль (обучающий курс с модулями, уроками и итоговыми заданиями).

## Как был создан

```bash
bash scripts/init.sh --profile course "Example Course" "EC" "Пример обучающего курса" "example@course.com"
```

## Что внутри

- `content/` — Gramax-каталог со структурой курса:
  - `00-overview/` — введение, prerequisites, порядок прохождения
  - `10-module-01-introduction/` — первый модуль с `lesson-01.md`
  - `20-module-02-example/` — второй модуль с `lesson-01.md`
  - `90-assessments/` — итоговые задания и тесты
  - `99-resources/` — дополнительные материалы и глоссарий
- `content/.doc-root.yaml` — properties для курса (Тип контента, Уровень сложности, Длительность, Статус, Prerequisites)
- `CLAUDE.md`, `AGENTS.md` — заполненные шаблоны проекта (placeholder'ы заменены)
- `.claude/plugins/project/agents/tech-writer-agent.md` — **resolved version** с применённым instructional designer override. Маркер `<!-- GENERATED -->` сверху файла.

## Что отсутствует (по spec course profile)

- `content/00-project/` — нет delivery-структуры (ADR, plans, critical-path)
- `content/30-requirements/` — курс не содержит технических требований
- `content/40-architecture/` — архитектурные артефакты не нужны учебному каталогу
- `content/60-implementation/`, `content/70-operations/` — internal-only, не входят в курс

## Профиль course — особенности

- **Активные subagents:** pm, tech-writer (core); ba, researcher (optional)
- **Disabled:** sa, dev, devops, qa, devsecops, compliance (курс не пишет код / ops)
- **Override `tech-writer`:** Instructional designer variant — second-person instructional tone, обязательный блок Learning objectives, структура урока recap → материал → practice → check your understanding
- **Нумерация модулей:** шаг 10 (`10-module-01-*`, `20-module-02-*`) оставляет резерв для вставки новых модулей без переименования существующих

## Что демонстрирует пример

1. **Override mechanic в действии.** `tech-writer-agent.md` — результат merge: base + delta из `docs/overlays/profiles/course/agent-overrides/tech-writer.md`. Маркер `<!-- GENERATED by scripts/_resolve_agents.py -->` сверху.
2. **Профиль-специфичный scaffold.** Структура `content/` (00-overview / 10-module / 20-module / 90-assessments / 99-resources) типична для обучающего курса — не для delivery-проектов.
3. **Instructional tone.** `lesson-01.md` в каждом модуле демонстрирует структуру урока: Learning objectives → Recap → Материал → Practice → Check your understanding.
4. **Properties курса.** `.doc-root.yaml` добавляет Уровень сложности (Beginner/Intermediate/Advanced), Длительность и Prerequisites — специфичные для учебных материалов.

## Как обновить пример

После изменения course манифеста или scaffold'а пересоздай example вручную:

```bash
TMP=$(mktemp -d)
cp -r . "$TMP/course-example"
rm -rf "$TMP/course-example/.git" "$TMP/course-example/.worktrees"
cd "$TMP/course-example"
git init -q && git add -A && git commit -q -m "snapshot" --allow-empty
bash scripts/init.sh --profile course "Example Course" "EC" "Пример обучающего курса" "example@course.com"
# Скопируй артефакты обратно в examples/course-example/
```

## Для чего это пример

Static snapshot для новых пользователей шаблона. Контрастирует с:
- `examples/project-example/` — delivery-проект (полная структура с ADR/req/arch/impl/ops)
- `examples/kb-team-example/` — internal team KB (onboarding/runbook/role/incident)
- `examples/kb-product-example/` — customer-facing docs (getting-started/guides/reference/troubleshooting)

Четыре примера вместе показывают, как один и тот же шаблон даёт разные типы контентного каталога в зависимости от профиля.
