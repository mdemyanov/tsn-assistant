# Example: kb-product profile

Этот каталог — пример проекта, инициализированного как `kb-product` профиль (документация продукта для внешних читателей).

## Как был создан

```bash
bash scripts/init.sh --profile kb-product "Example Product" "EP" "Example documentation for kb-product profile" "example@product.com"
```

## Что внутри

- `content/` — Gramax-каталог с 4 разделами:
  - `getting-started/` — quickstart-страницы для новых пользователей
  - `guides/` — пошаговые сценарии
  - `reference/` — API / CLI reference
  - `troubleshooting/` — типовые проблемы и FAQ
- `content/.doc-root.yaml` — properties для customer docs (Тип контента, Версия продукта, Аудитория)
- `CLAUDE.md`, `AGENTS.md` — заполненные шаблоны проекта (placeholder'ы заменены)
- `.claude/plugins/project/agents/tech-writer-agent.md` — **resolved version** с применённым customer-facing override (демонстрирует override mechanic в действии). Маркер `<!-- GENERATED -->` сверху файла.

## Что отсутствует (по `op: delete` в kb-product manifest)

- `content/00-project/` — нет delivery-структуры (ADR, plans, critical-path)
- `content/30-requirements/` — customer docs не имеют функциональных требований
- `content/40-architecture/` — архитектура продукта не публикуется наружу
- `content/60-implementation/`, `content/70-operations/` — internal-only

## Профиль kb-product — особенности

- **Активные subagents:** pm, tech-writer (core); researcher, ba, compliance (optional)
- **Disabled:** sa, dev, devops, qa, devsecops (kb-product не пишет код / ops)
- **Override `tech-writer`:** Customer-facing variant (без жаргона команды, version pinning, customer journey-driven structure)

## Что демонстрирует пример

1. **Override mechanic в действии.** `tech-writer-agent.md` — это не базовый промпт, а результат merge: base + delta из `docs/overlays/profiles/kb-product/agent-overrides/tech-writer.md`. Маркер `<!-- GENERATED by scripts/_resolve_agents.py -->` сверху.
2. **Профиль-специфичный scaffold.** Структура `content/` (getting-started/guides/reference/troubleshooting) типична для customer docs — не для delivery-проектов.
3. **Удаление internal-разделов.** `op: delete` в manifest убирает `00-project`, `30-requirements`, `40-architecture`, `60-implementation`, `70-operations` — всё, что не для внешнего читателя.

## Как обновить пример

После изменения kb-product манифеста или scaffold'а пересоздай example вручную:

```bash
TMP=$(mktemp -d)
cp -r . "$TMP/regenerate" && cd "$TMP/regenerate"
rm -rf .git && git init -q -b main
git -c user.email=t@x -c user.name=t commit --allow-empty -q -m baseline
bash scripts/init.sh --profile kb-product "Example Product" "EP" "Example documentation for kb-product profile" "example@product.com"
# Скопируй артефакты обратно в examples/kb-product-example/
```

## Для чего это пример

Static snapshot для новых пользователей шаблона. Контрастирует с:
- `examples/project-example/` — delivery-проект (полная структура с ADR/req/arch/impl/ops)
- `examples/kb-team-example/` — internal team KB (onboarding/runbook/role/incident)

Три примера вместе показывают, как один и тот же шаблон даёт три разных типа контентного каталога в зависимости от профиля.
