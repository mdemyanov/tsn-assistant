## Описание

UC-S1 — семантический поиск похожих объектов по **атрибутному вектору** issue-объекта (composite_extended). Использует векторы, наполняемые UC-V1. Возвращает top-K объектов, ранжированных по cosine similarity.

Поддерживает три режима:
- **same-class:** `issue → issue` (primary PoC use case);
- **cross-class:** `issue → knowledgeBase$article`, `issue → problem`;
- **free-text:** произвольная строка → issue/KB/problem.

UC-S1 — read-only по отношению к SMP. Никаких записей в карточки не производится. Отметки «связанная заявка», «дубль», «связанная проблема» ставит оператор вручную или через UC-C1.

**Зависимость от UC-V1:** если вектор issue ещё не посчитан (UC-V1 не отработал), UC-S1 возвращает ошибку «vector not ready», а не пустой список.

## Функциональные требования

- **FR-001. Поиск по объекту.** Сервис принимает `{source_id, source_meta_class}`, берёт атрибутный вектор источника из pgvector и возвращает top-K объектов (по умолчанию K=10) по cosine similarity.
- **FR-002. Free-text поиск.** Сервис принимает `{text, target_classes}`, формирует embedding через `text-search-query` (ADR-010), возвращает top-K из целевых классов.
- **FR-003. Параметр K.** Настраиваемый на уровне запроса. Default = 10. Верхний предел ≤ 100.
- **FR-004. Фильтр по target_classes.** Запрос принимает фильтр по FQN. Default — все векторизованные классы.
- **FR-005. Same-class и cross-class.** Реализует оба режима. Способ (один индекс vs union) — в ADR.
- **FR-006. Поля в ответе.** Каждая запись: `object_id`, `meta_class`, `score` (cosine similarity), `status` (workflow-статус объекта на момент запроса).
- **FR-007. Исключение source из выдачи.** Объект-источник никогда не возвращается в top-K.
- **FR-008. ACL для KB-статей.** Статьи KB, недоступные текущему пользователю по `kbAccesses`, исключаются из выдачи.
- **FR-009. Фильтр статусов workflow.** По умолчанию исключаются объекты в финальных нерабочих статусах (`closed` для KB, `cancelled`/`not_actual` для issue/problem). Параметр `include_closed=true` переключает поведение.
- **FR-010. Ошибки.** При отсутствии вектора источника возвращается `VectorNotReady`, а не пустой список. Структура ошибок без stack-trace (CLAUDE.md).
- **FR-011. Логирование.** Каждый запрос: `correlationId`, длина free-text (не сам текст), `targetClasses`, K, длительность, число результатов.

## Нефункциональные требования

- **NFR-S1-001. Latency p95.** End-to-end ≤ 500 ms на корпусе 100k объектов при HNSW с ef_search=40. Финальный SLA — после первого smoke-замера, фиксируется в ADR.
- **NFR-S1-002. Качество (черновой).** На offline-eval: Recall@10 ≥ 0.80 (primary), MRR@10 ≥ 0.50 (primary). Финальные пороги — после offline-eval, в ADR.
- **NFR-S1-003. Тенант-изоляция.** Поиск не возвращает объекты других тенантов.
- **NFR-S1-004. Безопасность.** Сырые тексты атрибутов в ответе не возвращаются. Только `object_id`, `meta_class`, `score`, `status`.
- **NFR-S1-005. Предсказуемость.** При отсутствии совпадений — пустой список (не ошибка).

## User Journey

### Journey-1. Оператор на карточке заявки

1. Оператор открывает карточку заявки `I`.
2. UI запрашивает у UC-S1 top-10 похожих: `{source_id=I.id, source_meta_class='issue', target_classes=['issue','knowledgeBase$article','problem'], K=10}`.
3. UC-S1 проверяет наличие вектора для `I`. Если нет — `VectorNotReady`; UI показывает «Похожие пока считаются».
4. UC-S1 выполняет поиск, применяет ACL (FR-008), фильтр статусов (FR-009), исключает `I` (FR-007).
5. UI показывает три списка: «Похожие заявки», «Связанные статьи KB», «Возможные проблемы».
6. Оператор переходит по ссылке — открывается карточка соответствующего объекта в SMP.

**Альтернатива:** у оператора нет доступа к наиболее близкой KB-статье — она не появляется, следующая по релевантности занимает её место.

### Journey-2. Аналитик — агрегированный отчёт

1. Аналитик выбирает эталонную заявку `I_ref`.
2. Запрос: `{source_id=I_ref.id, target_classes=['issue'], K=100, include_closed=true}`.
3. UC-S1 возвращает список заявок.
4. Аналитик группирует результат по подклассам, услуге, исполнителю.
5. Аналитик передаёт сводку в обсуждение — инициировать ли `problem` / изменение услуги.

### Journey-3. Автор статьи KB перед публикацией

1. Автор готовит черновик; нажимает «Найти похожие».
2. Free-text запрос: `{text=draft_title+draft_content, target_classes=['knowledgeBase$article'], K=10}`.
3. UC-S1 строит embedding через `text-search-query`, ищет в KB-индексе.
4. Автор видит список похожих статей и решает: публиковать новую, расширить существующую.

## Бизнес-правила

- **BR-001. Whitelist классов-источников.** Поиск «по объекту» допустим только для FQN из whitelist векторизованных классов (UC-V1). Иначе — ошибка `SourceNotVectorized`.
- **BR-002. kbAccesses.** KB-статья возвращается только если у пользователя есть доступ по `kbAccesses`. Фильтрация post-aggregation (к `parent_id`), не к `chunk_id`.
- **BR-003. Источник не в выдаче.** Всегда (FR-007).
- **BR-004. PII в логах.** Полный текст free-text запроса не пишется в лог. Только длина + truncated hash.
- **BR-005. Ground truth для eval.** Оценивается по `issue.duplicates` / `issue.duplicatesRL`, `problem.issues`, `slmService` (методология из `content/10-domain/research/similarity-eval.md`).
- **BR-006. Тенант-изоляция.** Объекты чужого тенанта не возвращаются.
- **BR-007. UC-S1 не модифицирует SMP.** Read-only.

## Доменные события

- **SimilaritySearchRequested** (`source`, `targetClasses`, `K`, `mode`, `correlationId`) — UC-S1 принял запрос.
- **SimilaritySearchCompleted** (`correlationId`, `resultCount`, `latencyMs`) — запрос обработан.
- **SimilaritySearchFailed** (`correlationId`, `errorCode`, `reason`) — ошибка.
- **VectorMissing** (`source`, `correlationId`) — вектор источника не найден.

## Acceptance Criteria

- [ ] **AC-001.** Запрос по существующему объекту возвращает top-K результатов (K=10 по умолчанию).
- [ ] **AC-002.** Явный K — возвращает ровно K записей или меньше (если кандидатов не хватает).
- [ ] **AC-003.** Free-text запрос на репрезентативной выборке возвращает непустой список.
- [ ] **AC-004.** Запрос `target_classes=['knowledgeBase$article']` не возвращает ни одного `issue` или `problem`.
- [ ] **AC-005.** Cross-class запрос (`issue` → `[knowledgeBase$article, problem]`) возвращает объекты обоих типов в одной упорядоченной выдаче.
- [ ] **AC-006.** Объект-источник никогда не в результатах (100 случайных запросов).
- [ ] **AC-007.** Пользователь без доступа к KB-разделу `S` не получает ни одной статьи из `S`; пользователь с доступом — получает (BR-002).
- [ ] **AC-008.** Объекты в финальных нерабочих статусах не возвращаются по умолчанию; `include_closed=true` включает их.
- [ ] **AC-009.** Запрос по объекту без вектора возвращает `VectorNotReady`, не пустой список и не 500.
- [ ] **AC-010.** Запрос под тенантом T2 не возвращает объекты тенанта T1.
- [ ] **AC-011. Качество (черновой).** Recall@10 ≥ 0.80, MRR@10 ≥ 0.50 на offline-eval (методология `similarity-eval.md §5`). Финальные пороги в ADR. Обоснование порога Recall@10 ≥ 0.80: соответствует стандарту ServiceNow Predictive Intelligence target для enterprise ITSM similarity search.
- [ ] **AC-012. Latency (черновой).** p95 ≤ 500 ms на корпусе ≥ 100k объектов после warm-up. Финальные пороги — после первого smoke-замера в ADR.
- [ ] **AC-013.** Логи содержат `correlationId`, длительность, `resultCount`; не содержат полный текст free-text (BR-004).
- [ ] **AC-014.** Ошибки возвращаются без stack-trace в теле ответа; stack — в логах с `correlationId`.
