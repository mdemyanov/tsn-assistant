## Описание

UC-C1 — near-duplicate detection и кластеризация SMP-объектов на основе **атрибутного вектора** (composite_extended). Использует векторы UC-V1.

Два режима:
- **Сценарий А (online):** при регистрации заявки — top-5 похожих с меткой уровня совпадения. Только подсказка, никакого автоматического связывания.
- **Сценарий Б (batch):** еженедельная джоба → отчёт с группами потенциально однотипных заявок за окно.

Ground truth: `issue.duplicates` / `issue.duplicatesRL` — ранее проставленные операторами связи (2,4 % заявок на llm2, что означает noisy precision/recall на PoC, см. RES-009.1 §3a.4).

**UC-C1 отличается от UC-S1** тем, что C1 использует пороги («дубль» / «похожая») и группировку, а UC-S1 — просто ранжирование. UC-C1 ориентирован на near-duplicate detection с высоким порогом, UC-S1 — на semantic retrieval.

## Функциональные требования

### Сценарий А — online подсказка

- **FR-001.** При регистрации новой заявки возвращает ≤ 5 ближайших по composite_extended среди уже векторизованных `issue`.
- **FR-002.** Поиск среди того же подкласса `issue` (или всех подклассов — конфигурируемо).
- **FR-003.** Каждому кандидату присваивается уровень: **Дубль** (score ≥ 0.92), **Похожая** (0.85 ≤ score < 0.92). Кандидаты < 0.85 не возвращаются. Черновые пороги — финальные после offline-eval (OQ-C1-1).
- **FR-004.** Self-match исключается (кандидат с тем же id не возвращается).
- **FR-005.** Кандидаты, к которым у оператора нет доступа в SMP, исключаются (ACL наследуется из SMP-сессии).
- **FR-006.** Ответ: `object_id`, `meta_class`, `subject`, `status`, `score`, `label` ('Дубль'/'Похожая').
- **FR-007.** При таймауте (NFR-C1-001) — silent skip: оператор не видит ни ошибки, ни спиннера.

### Сценарий Б — batch-аудит

- **FR-008.** Еженедельная (конфигурируемо) джоба выгружает векторы `issue` + `problem` за окно (FR-009) и формирует группы near-duplicate.
- **FR-009.** Окно параметризуемо (default — последние 90 дней). Конкретные дефолты — OQ-C1-2.
- **FR-010.** Выход: отчёт с группами; для каждой группы — список объектов, avg/min similarity, тип, `subject` первого объекта.
- **FR-011.** Группы, целиком покрытые существующими `issue.duplicates` / `issue.duplicatesRL`, помечаются «известные» — не удаляются, нужны для оценки полноты.
- **FR-012.** Модуль предоставляет API `clusters_audit(period)`, возвращающий структурированный список кластеров со score'ами. Формирование отчёта (KB-статья, файл, e-mail) — **out of scope модуля**; реализуется на стороне caller'а (пример caller'а: SD AI Assistant). Разрешён OQ-C1-3 (2026-05-02), Owner: Демьянов.
- **FR-013.** Применимость: `issue` (primary), `problem` (secondary). KB и cross-class — out of scope PoC.

### Оценка качества

- **FR-014.** Ground truth: `issue.duplicates` и `issue.duplicatesRL` (151/6 259 = 2,4 % на llm2).
- **FR-015.** Offline-eval: Precision@T и Recall@T для T ∈ {0.80, 0.85, 0.90, 0.92, 0.95}.
- **FR-016.** Финальные пороги «Дубль» / «Похожая» — после offline-eval, в ADR.

## Нефункциональные требования

- **NFR-C1-001. Online latency.** Подсказка появляется ≤ 2 с на p95. Превышение → silent skip (FR-007).
- **NFR-C1-002. Batch window.** Джоба укладывается в ночное окно обслуживания (черновой бюджет — ≤ 4 ч при сотнях тысяч векторов).
- **NFR-C1-003. Precision (online).** Precision для уровня «Дубль» ≥ 0.80 на ground truth `issue.duplicates`. Цель: оператор не тонет в ложных предложениях.
- **NFR-C1-004. Recall (online).** Recall дубликатов ≥ 0.50. Допускается пропуск части дублей при высокой precision.
- **NFR-C1-005. PII в выдаче.** В подсказке и отчёте — только `subject` и метаданные. `description` и `lastComment` не возвращаются клиенту.
- **NFR-C1-006. Идемпотентность batch.** Повторный запуск на тех же данных → сопоставимые группы (в пределах недетерминизма алгоритма).
- **NFR-C1-007. Наблюдаемость.** Каждый запуск пишет в лог: размер выборки, число групп, число known-дублей, длительность, версия модели, пороги.

## User Journey

### Сценарий А — online (happy path)

1. Оператор открывает форму регистрации `issue`, заполняет `subject`.
2. Система вычисляет embedding по composite_extended (или берёт из кеша).
3. KNN-поиск по pgvector, top-5 кандидатов.
4. Фильтр по порогу (FR-003), по ACL (FR-005).
5. Оператор видит ≤ 5 кандидатов с метками «Дубль» / «Похожая».
6. Никаких автоматических действий.

**Альтернативы:**
- A1: список пуст → UI показывает «Похожих не найдено» или скрывает блок.
- A2: таймаут → silent skip, регистрация продолжается.
- A3: cold start (нет векторов) → пустой список, нет ошибки.

### Сценарий Б — batch (happy path)

1. По расписанию запускается джоба `duplicate-audit`.
2. Выгрузка векторов за окно (FR-009).
3. Алгоритм группировки (cosine-threshold baseline, HDBSCAN+UMAP — резерв, OQ-C1-4).
4. Группы с known-дублями помечаются (FR-011).
5. Отчёт публикуется аналитику.
6. Аналитик разбирает вручную. Никаких автосвязываний.

**Альтернатива Б1:** превышение окна → аварийная остановка, **никакого частичного отчёта**. Эскалация DevOps.

## Бизнес-правила

- **BR-001. Никакого автомёрджа в PoC.** Связывание только вручную оператором или аналитиком.
- **BR-002. Ground truth — `issue.duplicates` / `issue.duplicatesRL`.** Иные источники в PoC не используются.
- **BR-003. ACL SMP.** Подсказки и отчёт не содержат объекты без прав доступа у получателя.
- **BR-004. PII в выдаче.** Только `subject` + метаданные (NFR-C1-005).
- **BR-005. Cold start допустим.** Нет векторов → пустой список, не ошибка.
- **BR-006. Whitelist — только из UC-V1.** UC-C1 не расширяет периметр PII.
- **BR-007. problem на llm2 не валидируется.** 3 объекта — noisy; precision/recall для problem не публикуются как PoC-метрика.

## Границы модуля (Out of scope)

- **Формирование отчёта о найденных кластерах** (KB-статья, файл, e-mail, интерфейс оператора) — реализуется на стороне caller'а. Модуль предоставляет только API `clusters_audit(period)`, возвращающий структурированный список кластеров со score'ами и метками (combined_score, label, known). Пример caller'а: SD AI Assistant (`/Users/mdemyanov/knowlage/sd-ai-assistant/CLAUDE.md`).
- **Автоматическое связывание / мёрдж дублей** — out of scope PoC и MVP (BR-001).
- **Cross-class кластеризация** (issue + KB + problem в одном кластере) — out of scope PoC (FR-013).

## Доменные события

- **SimilarIssuesRequested** (online) — оператор запросил подсказку.
- **SimilarIssuesSkipped** (online) — silent skip (таймаут / нет эмбеддинга).
- **DuplicateAuditRunStarted** (batch) — джоба стартовала.
- **DuplicateAuditRunCompleted** (batch) — завершилась: число групп, пар, длительность.
- **DuplicateAuditRunFailed** (batch) — не уложилась в окно или упала.

## Acceptance Criteria

- [ ] **AC-001.** На размеченном срезе `issue` (с `duplicates`/`duplicatesRL`) Precision для «Дубль» ≥ 0.80 при черновых порогах FR-003. Итоговые пороги — в ADR после offline-eval.
- [ ] **AC-002.** Recall «Дубль» ≥ 0.50 на том же срезе.
- [ ] **AC-003.** Online-подсказка возвращает результат ≤ 2 с на p95 (стенд `llm2`). Итоговое значение — после первого замера в DevOps-отчёте.
- [ ] **AC-004.** Подсказка не показывает заявок без ACL у оператора (выборочная проверка тестовым аккаунтом).
- [ ] **AC-005.** Подсказка не содержит `description` или `lastComment` — только `subject` + метаданные.
- [ ] **AC-006.** Batch-джоба отрабатывает на полном срезе `issue` + `problem` за окно в пределах NFR-C1-002. Отчёт сформирован, содержит ≥ 1 группу.
- [ ] **AC-007.** В отчёте группы, покрытые `issue.duplicates`, помечены «известные» и визуально отделены от новых кандидатов.
- [ ] **AC-008.** Повторный запуск batch-джобы на тех же данных → сопоставимый набор групп (детерминированность в пределах алгоритма).
- [ ] **AC-009.** Никаких автосвязываний по `issue.duplicates` в журнале SMP за время PoC.
- [ ] **AC-010.** Лог каждого batch-запуска содержит версию модели эмбеддингов и пороги — для воспроизводимости.
