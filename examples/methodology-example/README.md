# Example: methodology profile

Этот каталог — пример проекта, инициализированного как `methodology` профиль (методология / playbook / framework для команд, создающих нормативные системы).

## Как был создан

```bash
bash scripts/init.sh --profile methodology "Example Methodology" "EM" "Пример playbook'а методологии" "example@methodology.com"
```

## Что внутри

- `content/` — Gramax-каталог с 5 разделами (flat hierarchy, нумерация 10-50):
  - `10-principles/` — нормативные принципы методологии
  - `20-practices/` — конкретные практики с шагами и ролями
  - `30-playbooks/` — сценарии применения набора практик
  - `40-templates/` — шаблоны артефактов
  - `50-cases/` — иллюстративные кейсы применения
- `content/.doc-root.yaml` — properties для methodology docs (Тип контента, Статус, Уровень, Область применения)
- `CLAUDE.md`, `AGENTS.md` — заполненные шаблоны проекта (placeholder'ы заменены)
- `.claude/plugins/project/agents/tech-writer-agent.md` — **resolved version** с применённым methodology override (prescriptive voice). Маркер `<!-- GENERATED -->` сверху файла.

## Профиль methodology — особенности

- **Активные subagents:** pm, tech-writer (core); researcher, compliance (optional)
- **Disabled:** ba, sa, dev, devops, qa, devsecops (methodology не пишет код / ops / delivery-артефакты)
- **Override `tech-writer`:** Prescriptive methodology variant — нормативный голос («команда должна», «практика требует»), структура Принцип/Практика/Playbook, явное обоснование каждого правила

## Что демонстрирует пример

1. **Override mechanic в действии.** `tech-writer-agent.md` — результат merge: base + delta из `docs/overlays/profiles/methodology/agent-overrides/tech-writer.md`. Маркер `<!-- GENERATED by scripts/_resolve_agents.py -->` сверху.
2. **Prescriptive scaffold.** Структура `content/` (10-principles → 20-practices → 30-playbooks → 40-templates → 50-cases) отражает логическую прогрессию от нормативной основы к конкретным инструментам.
3. **Нет delivery-разделов.** В отличие от `project`-профиля, отсутствуют `30-requirements/`, `40-architecture/`, `60-implementation/`, `70-operations/` — methodology не описывает delivery.

## Как обновить пример

После изменения methodology манифеста или scaffold'а пересоздай example вручную:

```bash
TMP=$(mktemp -d)
cp -r . "$TMP/methodology-example"
rm -rf "$TMP/methodology-example/.git" "$TMP/methodology-example/.worktrees"
cd "$TMP/methodology-example"
git init -q && git add -A && git commit -q -m "snapshot" --allow-empty
bash scripts/init.sh --profile methodology "Example Methodology" "EM" "Пример playbook'а методологии" "example@methodology.com"
# Скопируй артефакты обратно в examples/methodology-example/
```

## Для чего это пример

Static snapshot для новых пользователей шаблона. Контрастирует с:
- `examples/project-example/` — delivery-проект (полная структура с ADR/req/arch/impl/ops)
- `examples/kb-team-example/` — internal team KB (onboarding/runbook/role/incident)
- `examples/kb-product-example/` — customer-facing документация продукта
